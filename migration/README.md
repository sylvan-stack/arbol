# Python Driver migration checks

These development checks implement SYL-95 without changing the shared Node build tool, launchers or conformance assertions. They are not a shared Driver runtime or a public library. Claude must pass the complete 38-scenario suite; Codex retains the five original scoped conformance groups and its unfinished feature tasks.

The retained TypeScript baseline is Claude `89322877059cb0cdeb6f549d6338d3863adce710` and Codex `37daaf853ae1f4d5382a316b5c7da683b057dda1`. Keep separate checkouts at those commits, install their development dependencies and compile them with Node 24. The current Python artifacts have their own pinned CPython interpreter; baseline preparation requires Node and npm only.

`generate-baseline.mjs <baseline-folder> <output-folder>` imports only the separately compiled baseline modules. It records source commits, 14 histories with incremental snapshots, Unicode/control/lone/split surrogate cases, decoded-image fingerprints, chat keys, Claude UTF-16 folder encoding, and the Keychain service formula. The committed copies are `tests/fixtures/migration-vectors.json` in each Driver. The Claude split-surrogate defect is explicitly corrected in the published DRV-6 migration amendment; the original result is retained alongside the canonical result. No other mismatch may be normalized away.

`generate-json-vectors.mjs <output-file>` records 12 additional independent Node JSON serialization cases: negative zero, exponent thresholds, IEEE-754 integer rounding, property order, controls and surrogate escaping. Each Driver's `tests/fixtures/migration-json-vectors.json` preserves the original input text as well as the expected compact output.

`verify-compatibility.py --baseline <folder> --claude <packaged-entry> --codex <packaged-entry> --output <record>` exercises both implementations through their command lines. It tests bidirectional Subscription read/write/removal, eight competing mixed-language automatic account reservations, format-1 permissions, native continuation in both directions with Unicode and images, duplicate run IDs, peer stopping in both directions, killed-owner cleanup election, preservation of a newer map entry, reused-PID protection, and higher-format refusal. Every case has a private temporary home/state and uses the retained vendor stand-in, with no vendor requests. Select Node 24 on PATH or with `ARBOL_NODE_EXECUTABLE`; `--mode baseline-harness-rehearsal` explicitly labels a self-check that runs the baseline twice and is not Python migration evidence.

For an intermediate single-driver check, `--drivers claude` or `--drivers codex` narrows the recorded scope. Completion evidence uses the default scope of both drivers. Packaged checks retain the artifact manifest's source, interpreter and digest separately from the current checkout's commit.

`probe-vendors.py --claude <packaged-entry> --codex <packaged-entry> --claude-state <existing-test-state> --codex-state <existing-test-state> --output <record>` records fresh no-prompt evidence using the packaged Python programs. It checks disposable version-probe state, the installed tool versions, the designated `test-anthropic`/`test-chatgpt` account/catalog/usage operations and Claude's complete `dev probe`. Account payloads are reduced to shapes. Owner configuration is compared by file metadata without reading credential contents. The script submits no inference input and does not sign in a new account.

The standalone packaging and offline registry rehearsal live independently in each Driver's `scripts/`. `verify_build.py` uses only disposable fixture repositories/registries and explicitly synthetic registry checks; it does not establish a working production Build. Claude's production `arbol-build.json` retains real packaged unit, complete contract, and exactly one test-account `dev build-check` gate. The Codex artifact is a development candidate at Build 0 until SYL-92/SYL-94 finish.

Evidence belongs to the applicable Artifact Corpus, with source, artifact, runtime and tool provenance. Historical TypeScript records stay available and must not be represented as Python validation. Publication changes use `.claude/linear-publish/edit.py` and `conv.py`; local specifications remain the originals.
